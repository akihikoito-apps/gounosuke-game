# 最難関コースの議論・第1回（Codex 提案）

作成日：2026-10-08。ジョブ91に基づく設計レビュー。実装・絵の変更はしていない。

## 1. 提案の中心：顔を残し、柄と隠れ場所で迷わせる

**まずはコース10を基準に、ふち線0.28・最大3人・迷彩帽子・難しい配置を優先する試遊版を提案する。** 限界比較は0.25まで。顔の縮小・背景色への同化・ヒントの弱体化は採用しない。難しさの上限は「何秒も見つからない」ではなく、「静止画に発見の根拠があり、ヒントで納得して見つけられる」までとする。

以下の効き目は、コードから説明できる挙動を除いて**推測**。試遊に基づく結果ではない。数値目標も今回の比較用の仮説であり、年齢別の能力基準ではない。

- 4〜6歳と家族の遊びを維持する。減点・時間切れ・怖い演出・課金・広告・外部通信を追加しない。ヒントは無料・無制限、好きな順で見つけられる。
- `LIMITS` の全体可視率45%以上、服20〜92%、高さ170以上、画面内余白6、個体間のすきま4、顔が見える条件を維持する。新しい隠れ場所にも適用する。
- 「目と口の判定点が遮られていない」だけでは不十分。実際の目・口全体が見え、顔と分かることを画像でも確認する。顔の色・線・大きさは難易度の操作対象にしない。
- 初回は既存の3背景・3体を使う。量産より、配置の選び方と見つけた瞬間の納得感に手間をかける。方針資料の「視覚テスト型・動くと見える型をやらない」に合わせる。

## 3. 最難関コースの具体案

### 推奨の1行（新しい項目を含む設計案）

既存10をすぐ置換せず、試遊用の候補として比較する。下表は現行の型へそのまま貼れるコードではない。

| 案 | spots | variant | outline | maxChars | hat | umbrella | 新しい項目 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 最難関候補H | all | exact | 0.28 | 3 | `{ rate: 1, style: 'camo' }` | `{ rate: 0.4, style: 'camo' }` | `placementPolicy: 'hard-ranked'`, `countPolicy: 'max-feasible'`, `decoyCount: 0`, `hintStyle: 'static'` |

傘0.4はコース10の0.8より低い。**傘を増やすほど難しいとはまだ言えないための比較用の値**。帽子は頭の目印を減らすが、傘は大きい輪郭・軸・タップ面積を増やす。0 / 0.4 / 0.8の比較で逆なら変更する。率1の帽子も、安全に付かない場所には付けない。

### 新しい項目の仕様と作り方

1. **`placementPolicy: 'hard-ranked'`（中）**
   - `analyzeSpot()` が安全とする候補だけを対象とする。その中で服の領域一致率90%以上、服可視率25〜40%、全体可視率50%以上を「優先帯」とする。45%・20%ぎりぎりを初回の狙いにしない。
   - 優先帯の中で領域一致率が高い順、次に服可視率が低い順で評価する。同等候補はシードで順序を変える。難しさの計算値であって知覚難度の保証ではない。
   - 迷彩小物も領域一致率90%以上を優先する。現行の返り値 `AccFit` に一致率を追加するか、共通の測定関数を作り、検証と選別で同じ測り方を使う。70%という安全側の既存条件は緩めない。
   - 候補不足なら既存の安全なallへ戻す。空配置を返さず、安全条件を緩めない。優先帯の成立率を制作側の試遊記録に残す。現時点で各背景に何候補あるかは未計測。
   - 帽子rate=1による既存の装着可能候補優先と衝突するため、配置評価→帽子の適合評価を統合する。候補を単純に二重ソートしない。顔・重なり・画面内の条件を常に最優先とする。
2. **`countPolicy: 'max-feasible'`（中）**
   - 希望人数を `min(3, remaining)` にする。現行の最初の候補で確定する方法ではなく、競合しない候補の組合せを探索する。3人の安全な組合せがなければ2人、次に1人へ戻す。
   - 同人数なら上記の優先帯に入る人数が多い配置を選び、同点はシードで選ぶ。人数を確保するために安全基準を下げない。人数と難しい場所が両立しない背景は記録する。
   - 帽子・傘も含め、他の顔、本体、小物との関係を最終検証する。現行の小物判定は描画全体のピクセル検査ではなく、帽子の帯・毛糸の細部・傘の軸等には形状との差がある。最終描画も確認する。
   - 最大人数が毎回置ければ10発見は3+3+3+1の4画面。常時3人保証や10画面保証とはしない。保存の発見数・最後の1人を確認する。
3. **`decoyCount: 0`（初回は実装不要。導入時は中）**
   - Hではにせものを入れず、比較実験で0→1→2個。上限2個。顔・目・口がなく、クッションや布袋と分かる独自の静物だけを使う。頭と胴の完全なコピーにしない。
   - 導入時はシーンの装飾と位置情報を定義し、本物と同じ柄座標を使う。顔の保護範囲に描かない。他の当たり判定領域（許容距離22を含む）に重ねない。前景として遮蔽を増やす用途には使わない。
   - にせものを押しても現行の外れと同じ。減点・専用の失敗音を足さない。上部の対象人数に含めない。
4. **`hintStyle: 'static'`（中）**
   - 1段階目は現行の半径230の円。2段階目は同じ対象の顔の周囲に静止した明暗2重の枠を表示。枠は目・口を覆わず、顔の外側へ余白12シーン単位以上を取る。3段階目は現行の輪郭表示。
   - `currentHint()` の対象選択を共用し、顔の表示範囲は画像ガイドと形状から定義する。`sceneView.ts` で表示、`app.ts` のwiggle付与をこのモードでは行わない。アニメーションを止めても救済が機能することを確認する。
   - 現行の揺れは任意の救済であり、アクション型のゲームそのものではない。ただし今回の前提をより明確に守るため静止表示を提案する。**ヒントを弱める変更ではない**。静止枠の方が弱ければ、より明確にする。

試遊入口も必要。`startCourse()` は未解放コースを拒否するため、ご本人が90人探してから試す導線にしない。Claude側の実装で保護者領域に「最難関をためす」を設け、試遊中の10発見はメモリ内で数え、通常コースの解放・保存進捗を変更しない案を推す（中）。表へのno:11追加だけでは、コース数・保存仕様・画面との整合が取れない。

### 限界を探る比較案X（採用決定ではない）

Hから1要因ずつ、outlineを0.25、服可視率の優先帯を20〜30%、全体可視率を45%以上へ広げ、最後ににせものを最大2個追加する。顔、高さ170、色以外の手がかり、当たり判定22は維持する。小物迷彩の一致率目標は95%以上にして比較するが、成立しなければ未成立と記録する。

これを成人だけで先に比較し、その後、家族が希望する場合に短く共同試遊する。全部の変更を一度に入れて「難しかった」で終えない。顔を残す以上、大人には簡単という上限があり得る。その場合も顔を消す方向には進めない。

見つけた演出は難しくする対象にしない。現状は同じ位置で発見済み表示・星が出る。必要なら祝福後の星だけを約1秒で静める比較を行うが、顔と上部チェックは残し、未発見者の位置は変えない。

## 5. 「難しい」と「理不尽」の境目

| 観点 | 4〜6歳 | 大人・家族での挑戦 |
| --- | --- | --- |
| 発見の根拠 | 顔・口・輪郭を指して「いた」と言える。色名を知らなくてもよい | 柄のつながり、静物と顔の違いを注意深く見る余地がある |
| 押した結果 | 顔や身につけ物を押せば見つかる。順番で拒否しない | 同じ。精密タップの競技にはしない |
| にせもの | 静物として分かる形まで。人の形を精密にコピーしない | 事前に静物が混じると説明して最大2個を比較。ただし本物の顔は保護する |
| ヒント | いつでも進められ、最終段階で納得して押せる | 利用を成績上の失敗にしない。自分で使わない選択はできる |
| やめる・交代 | 残り人数や解放のために続ける圧力を足さない | 家族で相談・交代できる。大人向け制限を幼児画面へ持ち込まない |

境界を越える具体例は、口を1点だけ残して周囲を覆う、背景色との微小な差だけに頼る、正解を押しても順番が違うので無反応、最後の1人だけ極小、ヒントを押しても救済されない、である。大人が楽しめても幼児版の通常コースへ自動採用しない。

画面は1000シーン単位。表示幅360 CSS pxなら高さ170は約61 CSS px、当たり判定の余裕22は約7.9 CSS pxに相当する。これは変換例で、指定画像から実測した表示幅ではない。高さ基準だけで顔の読みやすさを保証しない。

## 6. 実装順と試遊で確かめること

### 段階と比較方法

1. **A：現行10、B：outlineだけ0.28、C：B＋難しい配置優先**を先に比較する（小→中）。同じ背景・キャラ・配置では線の差だけを比較できるようにする。配置を変える比較では同じシードでも同じ絵になるとは限らない点を記録する。
2. 次に帽子、傘0 / 0.4 / 0.8、人数方針を1つずつ比較し、Hを組み立てる。初回は各背景2配置の計6配置を成人で点検する。記憶による有利不利を減らすため提示順を入れ替える。
3. 子どもの試遊は希望した家族で、1回3画面までを目安に、嫌がればその場で終える。4歳側と5〜6歳側の観察を分ける。少人数の家族試遊では全年齢への一般化はしない。大人が先に答えを言った回は自力発見と分ける。
4. Hで納得して遊べると確認できたらXを1要因ずつ試す。新しい小物・場所・4人化はその後。Xの全要因を一度に通常コース10へ入れない。

### 記録するもの

- 背景、シード、希望人数と実人数、実際の帽子・傘・同時装着数、優先帯の成立／代替配置の使用。装着率の分母は出現人数。
- 最初の1人／最後の1人までの時間、1人ごとのヒント段階、顔を認識したタップと無作為な連打の違い、見つけた子の押し直し、にせものへのタップ。
- 「どこを見て分かったか」、ヒント後に納得したか、自発的に続けたい／交代したい／やめたいと言ったか。難しくても楽しいかを時間とは別に扱う。
- 記録は匿名の手元メモ。子どもの氏名・写真・外部送信を追加しない。新しい通信や常時収集機能を作らない。

### 試遊の暫定的な見直し基準（科学的な閾値ではない）

- 成人の比較では、Hの1人発見までの中央値が現行10の1.3〜2倍程度になるかを見る。速く見つかっても失敗ではない。遅延の原因が単なる小ささ・押しにくさなら採用しない。
- 子どもが30秒ほど手がかりを得られなければ、保護者がヒントや交代を提案する。画面内のタイマー・自動失敗・待ち時間にはしない。
- 最終ヒントを出しても対象を指せない、顔を狙って2回続けて押しても反応しない、「いるのに違うと言われた」と受け取る場合は、その配置を候補から外して原因を調べる。
- 3画面中2画面以上で全員に最終ヒントが必要なら、通常コース用としては戻す候補。嫌がる、顔を見分けられない場合は回数を待たずに止める。ヒント利用自体を悪い成績としない。
- 同じ場所ばかりになるなら優先帯を緩める前に、1背景あたり安全な候補が何個残るかを見る。難問用に最低3候補を確保する目標とし、未達なら「背景追加」より既存位置の調整を検討する。

## 7. 自分でも危ないと思う点・Claudeに反論してほしい点

1. **3人固定に近づけるのは、最難関化より作業量の増加かもしれない。** 1人だけを難しく配置した方が、1人あたりの発見は難しい可能性がある。Hの人数方針は比較で捨てられる。
2. **帽子100%でも難しくなる保証がない。** 毎回同じ帽子なら帽子を探すゲームになる。傘を減らす判断も未検証で、実際には頭の目印を覆う効果が勝つかもしれない。
3. **幾何学的な可視率を難しさと取り違える危険がある。** 服が20%しか見えなくても顔が孤立して目立てば簡単。評価値は候補選別に使い、最終的な採否は静止画と試遊で決める。
4. **優先帯90%・25〜40%が現存するか未確認。** 成立しない条件を表へ足すだけではコース10と変わらない。実装前に候補分布を出し、成立が乏しければCを撤回するか各背景1か所だけ追加する。
5. **にせものは最も反対されやすい。** 大人には面白くても4歳には意地悪に見える。顔なしでも「かくれている子」に見えたら失敗。Xからも削除してよい。
6. **0.25は描画の下限であって遊びとして安全な下限ではない。** 端末・照明・絵の陰影で差が出る。0.28の時点で不評なら0.32へ戻す。
7. **静止ヒントの追加は今回の難度議論には広すぎるという反論があり得る。** 現行の任意の揺れを残すなら、通常探索は静止のまま・動かなくても最終輪郭で解けることを最低条件とする。救済を弱める妥協はしない。
8. **「顔を残すと大人には簡単」の可能性を受け入れる必要がある。** 顔を背景に溶かして難度を稼ぐと、幼児向けの約束と柄の遊びを失う。大人の探索時間だけで通常版を判断しない。

第2回で決めたい順序は、(1)配置優先帯の実現性、(2)傘が難しくするか易しくするか、(3)1人と3人のどちらが狙いに合うか、(4)にせものを比較対象に残すか、である。最初の実装はA/B/Cまでに絞ってもよい。
