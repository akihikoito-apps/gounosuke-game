# 最難関コース・第3回：顔の一部を隠す成人用試遊

2026-10-08／ジョブ93。**主役は家具の裏からのぞく配置にする。両目を覆うサングラスは不採用、深い帽子は片目全体を残す形に修正する。** 第2回の「顔を隠さない」は今回の本人判断で更新する。通常コース1〜10には適用せず、最大3人・10人発見で終了・減点なし・時間制限なし・通常進捗を変えない方針を維持する。以下の数値は試遊用の提案値であり、実証済みの見やすさ基準ではない。

## 重要な穴と修正案

1. **サングラス単独でも条件違反。** 「のぞき＋サングラス」だけを禁止しても、濃い両レンズが両目を隠す時点で「片目は見える」を満たさない。額に上げる／傾けて片目全体を出す案に置き換える。深い帽子も両目を半分ずつ残す仕様にはせず、片目の輪郭・瞳を丸ごと残す。ハイライトだけ見える状態を片目可視と数えない。まずはのぞきと片目を残す帽子で試す。
2. **「同じ絵だから継ぎ目なし」は条件付き。** 現行 `src/ui/sceneView.ts` の背景は back→柄領域→over→minor、キャラの後にforeを描く。柄＋overだけでは最終背景の復元にならず、重なった別の柄、minor、境界外に伸びる縁や影を落とす。透過したoverを元のover上に直接足すと濃くなる箇所があり、不透明な柄で覆い直せる内側とは事情が違う。座標が同じでもクリップの半透明な端ではキャラの色が細く漏れ得る。
3. **柄の領域と、物が隠す形を分ける。** ソファは背・肘・丸い角・縁の影まで、カーテンはひだの外縁まで、生け垣は葉先までが対象。単純な柄領域で切ると輪郭だけがキャラの後ろに残る。コード描画では店のカウンター柄が y=590 からなのに天板は y=572〜598、x方向にも柄より広い。柄の四角だけを再描画すると天板の上側を顔が突き抜ける。ラグ・床・壁の柄は、裏に立てる家具として扱わない。
4. **窓は独立した構造が必要。** 現行のへやの窓はdecorにガラス面と桟がまとまっており、窓は柄領域でも既存spotでもない。overを窓全体に再描画すると、ガラスや景色ごとキャラを消すおそれがある。「奥の景色→ガラス内で切ったキャラ→桟・枠」の順を専用に定義する。透明ガラスや反射を重ねるなら、最後の合成で目が読めることも確認する。0.5倍の固定は採用せず、下の画面上の最低寸法を満たす倍率にする。
5. **判定とヒントを一緒に直さないと不公平になる。** 現行 `src/core/session.ts` のhitTestは全身・小物の形までの距離を使い、隠れた胴体も当たる。前景にpointer-eventsを設定するだけでは直らない。また現行の最終ヒントは全身の輪郭なので、そのままでは押しても当たらない胴体を強調する。配置の採否・描画・当たり判定・ヒントが、同じ最終可視形状を参照する必要がある。

## のぞきの描画を成立させる条件

- **物ごとの前面マスクを先に確定する。** キャラがいない完成背景を、表示中と同じ柄の原点・倍率・描画順・minorの表示条件で一度合成し、対象の物が覆う部分だけ復元する案を推す。別案は背景を奥と手前に分離して手前を一度だけ描くこと。どちらも、キャラの表示領域は同じマスクの補集合で切り、縁の色漏れ・二重合成を縮小表示で確認する。影だけの半透明部分は、完全遮蔽の領域として扱わない。
- 全背景をキャラの上に戻さない。物より上や横に出た顔まで消える。物の裏に入るキャラと、物の前に立つ別のキャラは描画順を分ける。今回まずは復元マスクが他の人物・小物と交差する配置を候補から外す。foreを後段で重ねる場合、その下地の復元へforeを含めて二重に描かない。
- PNG使用時とコード描画時で家具の縁は一致するとは限らない。専用マスクは実際に使う背景ごとに検証し、未対応の背景表現ではそののぞき候補を使わない。単純にクリップを一律に広げる対処は、目まで削るので避ける。
- 背景の読み込み対策は優先して実施する。backだけでなく柄タイル・over・必要なforeなど、今回の完成画面が使う画像の読み込みとデコードを待ち、マスクと配置も揃った画面をまとめて公開する。待機中はステージの表示と入力を止める。失敗時は完成した代替画面か再試行・戻り口へ進み、キャラだけを出さない。画面遷移後に古い読み込み完了処理が画面を公開しないことも確認する。

## 最低線：シーン座標ではなく表示後の大きさでも判定

画面上の数値はすべてCSS px。端末の画素倍率では増やさず、SVGの実表示倍率で換算する。窓枠・帽子・foreをすべて反映した**最終状態**で測る。

| 項目 | 成人用試遊の下限・扱い |
| --- | --- |
| 片目 | 片方の目全体が無遮蔽。実描画の目の幅・高さが各3px以上、遮蔽物の境界から1px以上離す。点だけの判定をしない |
| 可視の大きさ | 目を含む連続した頭部の可視部分が幅24px×高さ12px以上の外接枠を持ち、実際の可視面積が180px²以上。細い線だけで枠を満たさない |
| 見える割合 | 遮蔽前の頭部面積の20%以上、全身面積の5%以上を残す。双方とも透明余白・小物を除く。割合だけで極小表示を合格にしない |
| 見分け | 片目に加えて、耳・くるん毛・もこもこの頭の縁など、色以外の特徴を1つ残す。対象一覧は識別できる通常の顔を維持 |
| タップ | 可視形状から最大8pxの許容幅。ただし家具・桟の不透明な遮蔽部分を除外する。残った判定領域に24×24pxの押せる範囲を1つ確保できない候補は不採用。他の人物の判定領域との間隔は8px以上 |
| 最終ヒント | 可視部分の輪郭を2px以上の線で背景より前に静止表示。必要なら明暗の二重線。上記の押せる範囲に重なるマーカーも出し、隠れた胴体をタップ先として示さない |

ヒントは成人用だけ「周辺の円→見えている顔の周辺に静止マーカー→可視輪郭＋押せる位置」にする。3回以内に最終段階へ到達し、発見まで消さず、何回でも使える。動きによる露出を難度設計に使わない。ヒントを出したことでマーカーが入力を遮らないことも必須。

第2回の優先帯（全体可視50%以上、服25〜40%）や現行 `analyzeSpot` の全顔・高さ170・服20%以上の条件を、そのままのぞきへ適用すると狙う配置が落ちる。**成人用ののぞき・窓にだけ別の検証を設け、上記条件に置き換える。** 服が全く見えない候補では柄一致率を計算・順位付けの必須条件にしない。通常配置には従来の検証を残す。画面が狭く下限を割る場合は倍率か露出を増やし、それでも成立しなければ別候補にする。

## 組み合わせの規則

| 手段 | 同じ子に重ねてよいもの | 今回重ねないもの |
| --- | --- | --- |
| 家具のぞき | 服の背景柄、目を隠さない通常位置の背景柄帽子（最終可視条件を満たす場合のみ） | 窓、深い帽子、サングラス |
| 窓の奥 | 服の柄。倍率は最低寸法から決める | 家具のぞき、深い帽子、サングラス、追加の縮小 |
| 片目を残す深い帽子 | 帽子自体の背景柄、服の背景柄 | 顔を隠す前景、窓、サングラス、別の帽子 |
| 片目を出すよう傾けたサングラス | 服の背景柄 | のぞき、窓、深い帽子。濃い両レンズで両目を隠す形は単独でも禁止 |

顔を隠す主な手段は1人1種類。背景に成立する候補があれば、最大3人のうち**1人を家具のぞきまたは窓**にする。残りは片目帽子か通常の背景柄帽子を使い、サングラス修正版は別途見た目を確認してから加える。人数を揃えるため最低線を割らず、安全に置ける2人・1人へ減らす。のぞき候補がない場合の通常配置への代替は試遊記録で区別し、難化が成功したと数えない。

## さらに効きそうな案

**隠す量だけでなく、探す高さと向きを変える。** 現行の足元付近のspotに加え、ソファ背の上・カーテンの左右端・窓の左右の区画など、物理的に自然な場所を候補化する。同じ家具でも前回と異なる端や高さを選び、「いつもの足元を順番に見る」だけで解けないようにする。顔の色を薄める、点ほどに縮める、動きで知らせる、にせものを置くことには頼らない。窓は専用マスクが必要なので、最初はソファ・カーテン・カウンターの3種を優先する。

## 本人の試遊で確かめること：3つ

1. **初見の探し方が変わったか。** 第2回配置とのぞき配置で、どこを探したか・何が手がかりだったか・ヒントを何段階使ったかを比較する。順序を入れ替え、覚えた同一配置だけで比較しない。発見までの時間は観察記録に限り、制限や採点にはしない。
2. **見つけた後に迷わず押せるか。** 320×568、390×844、768×1024で、3体それぞれの片目・特徴を読めるか確認する。見えている顔付近への意図したタップ10回中9回以上が成功することを試行目標とし、失敗は難しさの成果に数えない。隠れた胴体・窓の桟では成功しないこと、3段目ヒントで全員を発見できることも確認する。
3. **初表示も完成後も自然か。** 初回読み込み・低速相当・再訪・画像失敗で、キャラだけの露出が1フレームもないか録画で確認する。家具の縁、葉先、天板、窓の桟に色漏れ・切れ目・二重の影がないか、PNGとコード描画、狭い画面でminorが省かれる状態でも確認する。通常1〜10の見え方・判定・ヒントも変わっていないことを確認する。
