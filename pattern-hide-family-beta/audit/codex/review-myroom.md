## 重要度順の指摘

### 1. P1：ドラッグ中の部屋切り替えで、別の部屋の同じ番号の物を操作できてしまう

- **場所**：`src/ui/myroomView.ts:281`（onClick）、`:82`（open）、`:326`（onMove）、`:381`（onUp）。
- **何が起きるか**：部屋切り替えは `room` と `list` を交換する一方、`drag.idx` / `pointerId` を残す。別の指による切り替え後に元の指のイベントが届くと、新しい部屋の同じ番号の物を動かす・しまう。DOM交換でイベントが届かなくなる場合も、drag が残り、その後の pointerdown が拒否される。ホームを経由した再入室でも open は drag を解除しない。
- **再現**：リビングのラグ（idx=0）を指Aで押したまま、指Bでしんしつへ切り替える。Aを動かして離す。しんしつのラグが動く、または以降のドラッグが受け付けられない経路がある。端末でのイベント配送による違いは未確認。
- **最小の直し方**：ドラッグ中のタブ・部屋切り替えを無効にするか、切り替え前に元の部屋のドラッグを明示的に中断・復元する。open/画面離脱でも解除し、操作対象の room を Drag に保持して不一致のイベントを破棄する。capture は再描画で消えない要素に保持する。

### 2. P1：pointercancel が床外・画面外の途中座標を保存する

- **場所**：`src/ui/myroomView.ts:262`、`:350`、`:410`。関連：`src/core/myroom.ts:156`。
- **何が起きるか**：移動中は座席を解除し、床外も含めた座標を list に書く。cancelDrag は開始時に戻すことも床へ収めることもせず保存する。物が空中や画面外に残り、再入室後にも引き継がれる。pointercancel の pointerId を見ないため、別の指の中断でも進行中の操作を終了してしまう。
- **再現**：家具や友だちを壁の上へドラッグした途中で、そのポインターに pointercancel を送る。保存された y が floorTop 未満になる。別の pointerId の cancel でも同じドラッグが終了する。
- **最小の直し方**：開始時の配置を保持し、中断時は復元する（棚から新規追加した物も取り消す）。イベントの pointerId を照合する。確定保存する方針なら、最低限床への補正・座席整合性の処理を通常終了と共通化する。

### 3. P1：validLayouts が不正な座席・循環・重複を受け入れる

- **場所**：`src/core/myroom.ts:146`（validLayouts）、特に `:157` と `:162`。利用側：`src/ui/myroomView.ts:176`、`:194`。
- **何が起きるか**：on の検証は整数・参照番号の範囲・自己参照禁止だけ。座る側が char か、対象が座れる item か、seat が実在するか、同じ席の重複、相互参照を検証しない。ブランコの存在しない席では `seat.x` の参照で描画が例外終了する。相互参照の二体は root がなく描画されない。ref の重複・範囲外の有限座標も通り、「1枚に1つ」や床内配置を保証しない。
- **再現**：コース9クリア相当で living に `[{ref:'item:swing',x:500,y:800},{ref:'char:koro',x:500,y:800,on:{idx:0,seat:99}}]` を保存して入室する。検証を通り、ブランコの描画で例外になる。また、二体の char に互いを指す on を付けると両方消える。
- **最小の直し方**：ref を完全一致で検証し、重複を拒否。on は char → on を持たない座席付き item に限定し、seat の範囲と占有重複を確認する。座標は床内へ補正する。不正な部屋は既存方針どおり初期化し、描画側にも無効な席を参照しない防御を入れる。

### 4. P1：ブランコから友だちをドラッグすると、親の変換が二重にかかる

- **場所**：`src/ui/myroomView.ts:178`（rider の入れ子）、`:320`、`:350`、`:358`、`:361`。
- **何が起きるか**：rider はブランコの transform と揺れる座板の内側にいる。ドラッグでは on だけを消し、部屋全体の座標で transform を設定するが、DOMは座板の子のまま。同じ親への appendChild では外へ出ないため、家具の移動・倍率・揺れが再び加わり、指から大きく離れる。離した後の redraw で戻るので操作中の位置と確定位置も一致しない。
- **再現**：ブランコに友だちを座らせ、その子を10px以上ドラッグする。ブランコを左右反転した場合も確認する。
- **最小の直し方**：降り始めた時点で表示上の足元座標を部屋座標へ変換し、rider を `.mr-objs` 直下へ移す。capture 対象を消さずに行い、その後は通常の友だちと同じ移動処理にする。開始座標には実際の座板の揺れも反映する。

### 5. P1：棚のセルから指でスクロールできず、奥のごほうびへ届きにくい

- **場所**：`src/ui/styles.css:522`、`:523`、`:575`。`src/ui/myroomView.ts:302`、`:329`。
- **何が起きるか**：棚本体は pan-x（横向きでは pan-y）だが、76px等のセルには touch-action:none がある。セル上で始めたスワイプはネイティブスクロールにならず、JSにも棚をスクロールする処理がない。セル間の狭い隙間から操作する必要が生じる。マウスのクリック中心の既存テストでは確認できない。
- **再現**：シールを多数獲得した iPhone の縦向きで「もの」を開き、セルの中央から左右へスワイプする。横向きではセル中央から上下へ操作する。CSS上の問題であり、実機での操作感は未確認。
- **最小の直し方**：棚方向のパンをセルにも許可し、部屋へ出す方向の移動と区別する。長押し後だけドラッグ開始、または前後ページボタンなど、子どもがセル上からでも全品に到達できる操作を用意する。

### 6. P2：横向きの棚ドラッグが「部屋に入った」と誤判定される

- **場所**：`src/ui/myroomView.ts:335`（特に `:338`）、`src/ui/styles.css:571`。
- **何が起きるか**：棚から追加する条件が SVG の下端との y 比較だけ。横向きでは棚が右側にあるので、棚の中を動かしただけでも条件を満たし、既存の同じ物を removeAt → 再追加する。棚内で離すと今度は removeAt されるため、スクロールしようとした動きで部屋の家具がしまわれ、座っていた子も降りる。
- **再現**：横向きでソファを置き、子を座らせる。棚のソファのセル上を10px以上動かして棚内で離す。SVG下端より上の位置で試す。
- **最小の直し方**：追加はポインターが実際の部屋描画領域に入った場合だけにする。矩形の左右上下に加え、余白を含む SVG の場合は toScene の座標でも範囲を検証する。既存物の除去は有効なドロップが確定するまで行わない。

### 7. P2：「視差効果を減らす」で前景が顔の前に止まり続ける

- **場所**：`src/ui/styles.css:501`、`src/ui/moverView.ts:64`付近の負の animation-delay、`src/ui/app.ts:428`。
- **何が起きるか**：reduce は非表示や安全な位置への退避ではなく paused。顔の上を通る時点で設定が有効になると、その位置で止まる。また、再描画すると経過時間由来の新しい負のdelayで別の位置に停止する。「長く隠さない」「描き直しても位置が飛ばない」をreduce時には満たさない。
- **再現**：コース6以降で前景が顔を横切るタイミングに reduce を有効化する。そのまま待ち、さらに別の友だちを見つけて再描画させる。実機確認は未実施。
- **最小の直し方**：reduce 時は少なくとも前景の movers を非表示にする。背景も固定表示にする場合は開始時刻に依存しない安全な位置を選ぶ。

## その他の確認・保留事項

- **パック境界**：`src/core/rewards.ts:32` の upcomingRewards、`src/ui/app.ts:487` のクリア報酬、`src/core/myroom.ts:89` の ownedItems / openRooms は権限で絞る。無料の人におにわ・コース6以降の家具・うみべの家具を出す経路は、確認した通常経路では見つからない。ベータの canPlay が常に true であることと、無料相当の権限関数での確認は区別する必要がある。既存の部屋E2Eは進捗を変えるだけで、無料権限への差し替え試験ではない。
- **パックが外れた後**：`src/ui/myroomView.ts:103` は残った要素の番号を組み直すため、単純な filter による on.idx のずれは防いでいる。ただし `:109` は座席だけを解除し、最後に見えていた位置ではなく古い p.x/y に戻す。さらにフィルター済み list を次の persist で保存するため、再有効化しても除外した家具の配置は戻らない。非表示中も配置を保持したい仕様なら、保存用配置と表示用配置を分ける。現状の仕様では復元保証が明記されていないため、改善事項として保留。
- **通常のしまう操作**：`src/ui/myroomView.ts:476` は乗っている子を降ろしてから splice し、以降の on.idx を減らしている。通常の単一ポインター操作でここだけを原因とする番号ずれは見つからない。棚の連打も findIndex による追加/削除の交互動作で、通常データでは同じ ref を増殖させない。ただし置いた物のセルを押すと即座にしまわれる意味は、薄色と小さな丸だけでは幼児には分かりづらい（推測）。置く/しまうの短い案内や絵による区別があるとよい。
- **棚からの capture**：`src/ui/myroomView.ts:302` は明示的な capture がなく、`:346` の redraw は押していたセル自体を交換する。タッチの暗黙captureや画面外での pointerup を取り逃がす可能性がある（端末依存、推測）。`lostpointercapture` の終了処理もない。上記1・2と合わせ、安定した親要素で capture と終了を管理し、棚からドラッグしたまま画面外へ出る手順を実機で確認する。
- **顔を隠す時間**：`tests/unit/movers.test.ts:46` 付近の検査は、moverPos の理想軌道・概算寸法・顔の一点を各 mover 単独で調べる。CSSの上下動、実画像の範囲、複数の連続遮蔽、周期末から周期頭への連続区間を保証するテストではない。通常時に3秒以上隠すことを確認したわけではなく、保証範囲の不足として記録する。前景全部の合成と実際の顔範囲でも確認するとよい。
- **タップと位置維持**：`.movers { pointer-events:none }` はタップを遮らない設計。外側の移動には経過時間による負のdelayがあり、通常時の大きな巻き戻りを抑えている。一方 `.mv-inner` の上下動は再描画で0から始まり、最大14 SVG単位程度の位相差が出うる。優先度は低いが内側にも経過時間を反映できる。
- **WKWebView**：px・transform-box:view-box・CSS変数を使うkeyframesが意図どおりSVG座標で動くかは、このWindows上の静的レビューと型チェックでは判定できない。互換性がある/ないとも断定しない。対象iOSで往復端、左右反転、画面回転、見つけた直後の再描画、reduce切り替えを確認すること。ネット接続禁止のため互換性資料の外部調査も行っていない。
- **幼児向けの大きさ**：棚セルは通常76px、小さい画面では58pxなので、セルそのものは比較的押しやすい設計。部屋の小さい物はSVGに縮小され、明示的な最小ヒット領域がないため、重なった小物の選択は難しい可能性がある（推測）。実機でボール等を複数の家具の手前/奥に置いて確認したい。文字列・題材に怖い/危険な表現は見当たらないが、全画像を画面表示しての視覚検査は未実施。
- **性能（推測）**：通常ドラッグは対象と同乗者の transform を更新する方式で、毎フレーム全体を描き直さない点はよい。確定・タブ切り替え時は stage と棚を丸ごと交換し、最大40要素ではSVG構築、画像・マスク、アニメーション再開始の負荷が出うる。movers 5つはCSSアニメーション中心で毎フレームのJS生成はない。現行データの重複なし最大は家具21種＋友だち6体の27要素で、40要素は通常操作より保存境界の試験条件。低性能iPhoneでのフレーム時間・メモリは未計測。まず計測し、必要なら差分更新を行う。
