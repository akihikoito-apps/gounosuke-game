## 指摘（重要な順）

### 1. [P2] キーボードのフォーカスを外すと、長押しを途中でやめても保護者ゲートが開く

- 場所: `src/ui/parent.ts:150`、`src/ui/parent.ts:165`（関連: `src/ui/app.ts:103`）
- 何が起きるか: 長押しタイマーを取り消すキーイベントは長押しボタン自身の `keyup` だけ。`blur` / `focusout` では取り消さないため、押し始めた後に Tab で移動してからキーを離すと、解除イベントが別の要素に届き、2.2秒後にパネルが開く。ウィンドウのフォーカス喪失でも、App 側が取り消すのはドラッグだけ。数字の問題は依然として必要だが、その後の「押し続ける」条件を満たさず通過できる。
- 具体的な再現手順: 「おとなの かたへ」→ 数字の問題に正答 → 長押しボタンで Space を押す → 2.2秒以内に Tab で「閉じる」へ移動 → Space を離す → 最初の押下から2.2秒待つ。
- 確認区分: イベント登録とタイマーの流れはコードで確認。上記のブラウザ操作結果は未実行のため**推測**。
- 最小の直し方: 長押しボタンの `blur` とウィンドウの `blur` でも `stopHold` を呼ぶ。ウィンドウに登録するリスナーはゲート終了時に解除する。上記の短い押下・フォーカス移動・キー解放でパネルが開かず、通常の長押しでは開くことを確認する。

### 2. [P2] 更新途中の新しい HTML が、古い版のオフラインキャッシュを壊し得る

- 場所: `src/sw-template.js:34`–`40`、`src/sw-template.js:44`（関連: `vite.config.ts:34`–`39`）
- 何が起きるか: 稼働中の旧 Service Worker がナビゲーションで取得した新しい HTML を、旧版の `CACHE` の `./` に上書きする。一方、新しいハッシュ付き JS/CSS は旧版のプリキャッシュ一覧に存在せず、通常の fetch 成功時もキャッシュに追加しない。新 Service Worker のインストールが通信断等で完了しなかった場合、旧キャッシュには「新 HTML と旧アセット」が残る。次回のオフライン起動で新 JS/CSS を取得できなくなる可能性がある。
- 具体的な再現手順: 版Aを一度開き SW の管理下にする → JS/CSS が変わる版Bを同じURLに配信 → Bの HTML と起動用アセットは取得できるが、Bの SW 更新取得またはプリキャッシュの一部が失敗する状態でリロード → 旧 SW が残っていることを確認 → HTTPキャッシュの助けを受けない状態で通信を切り、再起動する。Cache Storage のAの `./` がBの HTML であり、参照するBのアセットが欠けているか確認する。
- 確認区分: HTML の上書きとアセット未保存はコードで確認。更新失敗を伴う実ブラウザでの起動結果は未実行のため**推測**。既存の `tests/e2e/offline.spec.ts` は単一版でのオフライン再開を検査しており、この更新失敗ケースは含まない。
- 最小の直し方: バージョン付きプリキャッシュ内の起動 HTML をナビゲーション取得で上書きしない。オフライン時は稼働版のキャッシュを明示して、その版の HTML とアセットを組で使う。新しい組への切替は新 SW の `addAll` 成功後に行う。

### 3. [P2・配置条件付き] 同一オリジンの別パスに置いた版のキャッシュを削除してしまう

- 場所: `src/sw-template.js:3`、`src/sw-template.js:19`
- 何が起きるか: キャッシュ名と古いキャッシュの削除条件に Service Worker のスコープが含まれていない。Cache Storage はオリジン単位なので、同じホストの `/beta/` と `/family/` に異なる版を配信すると、一方の activate がもう一方のプリキャッシュも削除する。削除された側は、オフラインで再起動できなくなる可能性がある。
- 具体的な再現手順: 同一オリジンの2つのサブパスに内容の異なるビルドを配信 → 片方を開いてプリキャッシュを作る → もう片方を開いて SW を activate させる → 最初の版のキャッシュが消えたことを確認 → 通信を切って最初のパスを再起動する。
- 確認区分: 共通接頭辞による削除条件はコードで確認。複数パスでの運用有無・ブラウザでの再現は未確認のため**推測**。単一パスのみの運用ではこの指摘の条件に当たらない。
- 最小の直し方: キャッシュ接頭辞に `self.registration.scope` に由来する識別子を含め、削除対象を同じスコープの旧版だけに限定する。検索も `caches.match` 全体ではなく自分のキャッシュに限定する。
