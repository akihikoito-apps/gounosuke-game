# ジョブ97：発売前の最終点検と、持ち主からの相談への意見

## 書き込んでよい場所
`audit/codex/review-final.md` の1ファイルだけ。コード・絵・設定は変更しない（読むのは自由。読むだけのコマンドは可。ネット接続・公開・push はしない）

## 背景
持ち主（大人）は「そろそろ発売に向けて仕上げたい。最終点検をして、もっとこうすればいいという提案も歓迎」と言っている。遊ぶのは3〜6歳と親。Apple の Kids カテゴリ（5歳以下）で出す予定。本体無料＋追加パックの買い切り（パックは1つずつ選んで買える。セット販売も）。
画面写真：`audit/screens/*.png`（全画面）。実装：`src/`。企画：`strategy/PACKS_PLAN.md`・`strategy/APP_STORE.md`。

## 持ち主からの相談（それぞれ、おすすめ案と理由を書く）
1. **トップ画面に「あそびかた」のボタン**を置くか。置くなら、字が読めない子にも分かる見せ方（絵・動き）
2. **トップ画面に、追加パック（新しい友だち・背景）を買う入口**を置くか。Kids カテゴリの決まり（購入の前に保護者ゲート、子どもをあおらない）を守りつつ、親に気づいてもらえる置き方。入口の見た目・文言・ゲートの後の画面の構成
3. **「最新版が出たら、アップデートを知らせる帯」**を出したい。ただしこのアプリは「通信しない・データを集めない」と申告する予定（`native/check-www.mjs`・CSP で外部通信を禁止）。通信して App Store の版を調べるのか、通信せずに「あたらしく なったよ（何が増えたか）」を更新後に見せるのか、など。プライバシー申告・Kids カテゴリ・審査への影響を含めて
4. 現状、ベータ用に全パックが遊べる設定（`src/entitlements/entitlements.ts` の betaEntitlements）。持ち主の方針「課金したもの・進捗で開いたものだけ使える」に切りかえるときに、壊れる所・見落としやすい所

## 最終点検（重要な順に）
- 遊びとして：分かりやすさ、つまずく所、飽きる所、難しさの上がり方、ごほうびのペース
- 幼い子の操作：押しやすさ、誤操作、意味が分からない所
- 発売を止めるもの（審査で落ちる・クラッシュ・データが消える・説明と実装の食い違い）
- もっと良くする提案（すぐできる／発売後でよい に分ける）

## 書き方
`audit/codex/review-final.md` に。相談1〜4の答え → 発売を止めるもの → すぐ直したい所 → 発売後でよい提案、の順。場所（ファイル:行 または 画面写真の名前）と理由を添える。推測は推測と書く
